# Brief: fix security-audit items (owner approved 2026-10-30)

Source: `audit/NEEDS-VALIDATION.md` and `audit/REPORT.md` (Cloudflare security-audit skill, run-1). Read both first. Fix the six needs-validation items plus the logout/session item. Smallest effective changes at the last trusted decision point, each with regression tests. Keep all existing behaviour and tests (adjust a test only if it asserted the vulnerable behaviour; say which). Do not deploy, do not apply migrations remotely, do not touch secrets, calibration or scoring.

1. **CSRF on anonymous spend routes.** Every state-changing request (POST/DELETE on any `/api/*` route, guest or signed-in: mark, helpers, review, hit, reviews/moderate, history, auth, account…) must carry `X-Requested-With: bandexe` AND, when an `Origin` header is present, it must be the request's own origin (same scheme+host); otherwise 403 `csrf`. Also reject non-`application/json` Content-Type on JSON routes with 415. Update every client call (`src/lib/reviews.ts`, `src/lib/stats.ts`, `api.ts`, `cloud-request.ts`, `gemini.ts`, helpers, auth, history, sendBeacon users if any — switch beacons to fetch keepalive if needed) to send the header and JSON content type. Grep for every `fetch(` to `/api`.
2. **IPv6 rotation.** Before hashing the client address for guest allowances, review limits, hit/impact counters and replay keys, normalise IPv6 to its /64 prefix (IPv4 unchanged; handle IPv4-mapped IPv6). One shared helper, tested with compressed/expanded forms.
3. **Fail-open allowance.** If the guest allowance check errors or times out, refuse (503 with a calm "try again shortly" message, no provider call) instead of allowing. Signed-in/tester paths: same rule unless tester (tester may continue). Bound `/api/hit` D1 writes (see 6).
4. **Replay map exhaustion.** In `shared/traffic.ts`: cap entries per client key (e.g. ≤ 8) instead of only the global 512, evict the requester's own oldest entry rather than 503 for others, and do not retain entries for non-2xx outcomes.
5. **Body buffering.** Parse the request body once and pass the parsed value through to `handle` (no stringify/parse round-trips). Lower the default body cap to 64 KB for routes without images; keep the larger cap only for the mark route when a chart image is present (decide by route, then enforce by size while streaming).
6. **Visits counter inflation.** Put the visits increment in `/api/hit` behind the same small per-IP(/64)-per-day allowance used for browsers/students (e.g. ≤ 20 visits per key per day), so D1 writes are bounded.
7. **Logout / deletion session revocation.** Add migration `migrations/0004_session_epoch.sql`: `ALTER TABLE users ADD COLUMN session_epoch INTEGER NOT NULL DEFAULT 0`. Include the epoch in the signed session payload; `readSession` callers verify the cookie epoch equals the current DB epoch (the account-exists check already reads the users row — reuse that query). Logout increments the epoch. Account deletion must also make old cookies invalid after re-signup: keep a small `revoked_before` mechanism or store a deletion timestamp so a re-created user starts at an epoch/issue time that rejects older cookies (e.g. put `iat` in the session and keep `sessions_valid_after` per uid that survives deletion in a tiny table keyed by uid, pruned after 31 days). Update `tests/sqlite-d1.ts` schema setup accordingly. Old cookies without epoch should be treated as invalid (users simply sign in again).

Also correct the Privacy text if it overstates what account deletion removes (the audit noted it), in English and all 11 catalogues if the sentence is translated.
